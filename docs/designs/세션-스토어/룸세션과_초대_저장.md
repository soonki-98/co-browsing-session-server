# 룸 세션과 초대 저장 — 기술 설계도

> 기획: [docs/specs/세션-스토어/룸세션과_초대_저장.md](../../specs/세션-스토어/룸세션과_초대_저장.md)

## Overview

화면 공유 한 건의 진행 상태(`RoomSession`)와 시리얼 코드 → 룸 매핑(`Invitation`)을 도메인 엔티티로 정의하고, 각각의 in-memory 저장소를 둔다. 두 엔티티는 **TTL 10분**과 상태 전이 규칙을 도메인 메서드(`Transition`, `IsExpired`)로 캡슐화하고, 저장은 도메인이 선언한 포트(`Repository` 인터페이스)로 추상화한다. 구체 저장소는 `sync.Mutex`로 보호되는 맵이며, 만료 판정은 **별도 정리 goroutine 없이 조회 시점에 read-on-check 방식**으로 적용한다 — 조회(`Get`/`ResolveBySerial`)가 만료 항목을 발견하면 그 자리에서 삭제하고 sentinel 에러(`ErrExpired`)를 돌려준다. 구현 순서상 가장 안쪽(도메인 + 인프라)이므로 이후 service·interfaces 레이어가 이 포트를 주입받아 동작한다.

## Implementation Order

```
domain
 ├─ roomsession (RoomID, RoomSession, Status 전이, sentinel, SessionTTL, Repository port)   ← 지금 여기
 └─ invitation  (Invitation, sentinel, InvitationTTL, Repository port)                       ← 지금 여기
      │  (의존: invitation → roomsession.RoomID, serialnumber.SerialNumber)
      ▼
infrastructure/memory
 ├─ RoomSessionRepository (roomsession.Repository 구현)                                       ← 지금 여기
 └─ InvitationRepository  (invitation.Repository 구현)                                        ← 지금 여기
      │
      ▼
services  (roomsession.Service — 두 포트를 주입받아 Create/Activate/End 오케스트레이션, 보상 트랜잭션)  [후속 설계]
      │
      ▼
interfaces (POST /rooms 핸들러 등 — service 호출)                                              [후속 설계]
      │
      ▼
app (NewRoomSessionRepository / NewInvitationRepository 생성·주입, 라우팅 조립)               [후속 설계]
```

- **선행 의존성**: 없음. `domain/serialnumber`(`SerialNumber` 값 타입 + `Generator` 포트)는 이미 존재하며 본 설계에서 **변경 없음**.
- **후행 의존성**: `services/roomsession.Service`가 두 `Repository` 포트를 주입받아 사용한다(보상 트랜잭션 경계 = service 책임). `serialLength = 6` 상수는 도메인이 아니라 service(`internal/services/roomsession/service.go`)가 관리한다.

## Layer Mapping

| 기획 FR | 레이어 | 담당 유닛 |
|---------|--------|-----------|
| FR-1 (고유 식별·초기 "대기") | domain | `roomsession.NewID()`, `roomsession.New()` (Status=Waiting) |
| FR-2 (초대를 시리얼에 연결 등록) | domain + infrastructure | `invitation.New()`, `InvitationRepository.Create` (등록은 service가 오케스트레이션) |
| FR-3 (시리얼로 룸 조회) | domain + infrastructure | `invitation.Repository.ResolveBySerial`, `roomsession.Repository.Get` |
| FR-4 (미등록 시리얼 → 없음 알림) | infrastructure | `InvitationRepository.ResolveBySerial` → `invitation.ErrNotFound` |
| FR-5 (양쪽 합류 시 대기→진행) | domain | `RoomSession.Transition(StatusActive)` |
| FR-6 (종료로 전환) | domain | `RoomSession.Transition(StatusEnded)` |
| FR-7 (종료 시 초대 제거) | infrastructure | `InvitationRepository.Delete` (호출은 service `End` 흐름) |
| FR-8 (허용 안 되는 전이 거부) | domain | `Status.CanTransitionTo`, `Transition` → `ErrInvalidTransition` |
| FR-9 (10분 내 미진행 시 만료) | domain | `SessionTTL`/`InvitationTTL`, `New()`의 `ExpiresAt`, `IsExpired` |
| FR-10 (만료 조회 시 알림+제거) | infrastructure | `Get`/`ResolveBySerial`의 read-on-check → 삭제 + `ErrExpired` |
| FR-11 (중복 식별·시리얼 거부) | infrastructure | `Create` 중복 검사 → `ErrAlreadyExists` |
| NFR-1 (동시성 안전) | infrastructure | 두 repo의 `sync.Mutex` |
| NFR-2 (시리얼 로그 비노출) | (경계 레이어 책임) | 도메인/인프라는 시리얼을 로깅하지 않음 |
| NFR-3 (외부 저장소 없는 즉시 보관) | infrastructure | in-memory 맵 |
| NFR-4 (조회 시점 만료 판정) | infrastructure | read-on-check (백그라운드 작업 없음) |

## Data Structures

### domain — roomsession

```go
// internal/domain/roomsession/roomsession.go
package roomsession

const SessionTTL = 10 * time.Minute

type RoomID string

func (roomID RoomID) String() string { return string(roomID) }

func NewID() RoomID { return RoomID(uuid.NewString()) }

type RoomSession struct {
    ID        RoomID
    Status    Status
    StartedAt time.Time
    ExpiresAt time.Time // active 진입 시 zero(무기한)
}

func New(roomID RoomID) *RoomSession {
    now := time.Now()
    return &RoomSession{
        ID:        roomID,
        Status:    StatusWaiting,
        StartedAt: now,
        ExpiresAt: now.Add(SessionTTL),
    }
}
```

```go
// internal/domain/roomsession/status.go
package roomsession

type Status string

const (
    StatusWaiting Status = "waiting" // 발급됨, 양쪽 미접속
    StatusActive  Status = "active"  // 양쪽 접속, 진행 중
    StatusEnded   Status = "ended"
)
```

### domain — invitation

```go
// internal/domain/invitation/invitation.go
package invitation

const InvitationTTL = 10 * time.Minute

type Invitation struct {
    Serial    serialnumber.SerialNumber
    RoomID    roomsession.RoomID
    IssuedAt  time.Time
    ExpiresAt time.Time
}

func New(serial serialnumber.SerialNumber, roomID roomsession.RoomID) *Invitation {
    now := time.Now()

        Serial:    serial,
        RoomID:    roomID,
        IssuedAt:  now,
```

## Interfaces / Contracts

### RoomSession Repository (도메인 포트)

```go
// internal/domain/roomsession/repository.go
package roomsession

// Get은 read-on-check — 만료 세션 발견 시 삭제 후 ErrExpired 반환.
type Repository interface {
    Create(roomSession *RoomSession) (*RoomSession, error)
    Get(roomID RoomID) (*RoomSession, error)
    Update(roomSession *RoomSession) (*RoomSession, error)
    Delete(roomID RoomID) error
}
```

### Invitation Repository (도메인 포트)

```go
// internal/domain/invitation/repository.go
package invitation

// ResolveBySerial은 read-on-check — 만료 항목 발견 시 삭제 후 ErrExpired 반환.
type Repository interface {
    Create(invitation *Invitation) (*Invitation, error)
    ResolveBySerial(serial serialnumber.SerialNumber) (*Invitation, error)
    Delete(serial serialnumber.SerialNumber) error
}
```

### 도메인 행동 메서드 시그니처

```go
// internal/domain/roomsession/roomsession.go
func (roomSession *RoomSession) IsExpired(now time.Time) bool
func (roomSession *RoomSession) Transition(targetStatus Status) error

// internal/domain/roomsession/status.go
func (status Status) IsValid() bool
func (status Status) CanTransitionTo(targetStatus Status) bool

// internal/domain/invitation/invitation.go
func (invitation *Invitation) IsExpired(now time.Time) bool
```

`Transition` 내부 규칙:
- `CanTransitionTo(target)`가 거짓이면 `ErrInvalidTransition` 반환(상태 변경 없음).
- `target == StatusActive`이면 `ExpiresAt = time.Time{}`(zero, 무기한)으로 설정한 뒤 상태를 바꾼다.

### 상수

```go
const SessionTTL    = 10 * time.Minute // internal/domain/roomsession/roomsession.go
const InvitationTTL = 10 * time.Minute // internal/domain/invitation/invitation.go
```

`serialLength = 6`은 도메인이 아니라 application service(`internal/services/roomsession/service.go`)가 관리한다.

## Behavior

### RoomSession 상태 머신

```
  New(id)
    │
    ▼
 waiting ──(양쪽 WS 접속 → Transition(active): ExpiresAt=zero)──▶ active
    │                                                              │
    │ (TTL 직전 종료 / 비정상 종료)                                 │ (정상 종료 / 한쪽 이탈)
    └──────────────────── Transition(ended) ◀──────────────────────┘
                              │
                              ▼
                            ended  (종료, 재진입 불가)
```

유효 전이(`Status.CanTransitionTo`):
- `waiting → active` (허용)
- `waiting → ended` (허용)
- `active → ended` (허용)
- 그 외(`ended → active`, `active → waiting`, `ended → waiting` 등) → `ErrInvalidTransition`

### TTL / 만료 규칙

| 대상 | TTL | 생성 시 ExpiresAt | 무기한 처리 |
|------|-----|-------------------|-------------|
| RoomSession | `SessionTTL` 10분 | `New()`에서 `now.Add(SessionTTL)` | `Transition(StatusActive)`이 `ExpiresAt=zero` → `IsExpired`가 항상 false |
| Invitation | `InvitationTTL` 10분 | `New()`에서 `now.Add(InvitationTTL)` | 없음(초대는 상태 개념 없음, 존재=유효) |

- `RoomSession.IsExpired(now)` = `!ExpiresAt.IsZero() && now.After(ExpiresAt)` — active(zero) 세션은 절대 만료되지 않는다.
- `Invitation.IsExpired(now)` = `now.After(ExpiresAt)`.
- **만료 판정 시점 = 조회 시점(read-on-check)**. 별도 주기적 정리 goroutine 없음.
  - `RoomSessionRepository.Get`: 항목 발견 → `IsExpired(time.Now())`면 맵에서 `delete` 후 `roomsession.ErrExpired`.
  - `InvitationRepository.ResolveBySerial`: 항목 발견 → `IsExpired(time.Now())`면 `delete` 후 `invitation.ErrExpired`.
- 초대의 명시적 제거(종료 흐름)는 `Repository.Delete` — 호출 주체는 service의 `End` 흐름(후속 설계). 한 번 종료된 룸의 시리얼은 재사용되지 않는다.

### Sentinel 에러 정의 + 레이어별 번역

```go
// internal/domain/roomsession/roomsession.go
var (
    ErrNotFound          = errors.New("room session not found")
    ErrExpired           = errors.New("room session expired")
    ErrAlreadyExists     = errors.New("room session already exists")
    ErrInvalidTransition = errors.New("invalid status transition")
)

// internal/domain/invitation/invitation.go
var (
    ErrNotFound      = errors.New("invitation not found")
    ErrExpired       = errors.New("invitation expired")
    ErrAlreadyExists = errors.New("invitation already exists")
)
```

레이어별 번역 흐름(본 설계 범위는 domain/infrastructure까지, 이후는 참고):
- **domain → infrastructure**: 저장소가 도메인 sentinel을 그대로 반환(없음=`ErrNotFound`, 만료=`ErrExpired`, 중복=`ErrAlreadyExists`). 새 에러 타입을 만들지 않고 도메인 규약을 지킨다.
- **infrastructure → services**: service가 `errors.Is`로 분기하고, 맥락을 `%w`로 래핑(`fmt.Errorf("resolve invitation: %w", err)`)하거나 유즈케이스 에러로 번역(후속 설계).
- **services → interfaces(transport)**: 유즈케이스 에러를 HTTP 상태 코드로 매핑(후속 설계). 안쪽 sentinel을 트랜스포트가 직접 알지 않도록 service 경계에서 변환한다.

### 동시성 전략 (NFR-1, NFR-4)

- 두 in-memory 저장소는 모두 `sync.Mutex`로 전체 연산을 보호한다. read-on-check가 조회 중 `delete`(write)를 동반하므로 `RWMutex`의 RLock으로는 안전하지 않다 → 단일 `Mutex` + `defer Unlock`.
- 저장소는 호출자의 트랜잭션 경계를 모른다. 두 저장소에 걸친 원자성(룸+초대 동시 생성, 한쪽 실패 시 보상 롤백)은 **service**가 책임진다(후속 설계).
- 검증: `go test -race ./...`로 data race 부재 확인(아래 Test Plan).

## Test Plan

테스트는 도메인(순수 단위)과 인프라(저장소 동작)로 나누어 작성한다. 테이블 기반 + named subtest, 동시성 케이스는 `go test -race`.

### domain/roomsession (단위)

- `New(id)` → Status=`waiting`, `ExpiresAt ≈ StartedAt + SessionTTL` (AC-1)
- `Transition(StatusActive)` → Status=`active` 이고 `ExpiresAt.IsZero()` (AC-7)
- `Transition(StatusEnded)` (from waiting) 허용 (AC-8)
- `Transition(StatusEnded)` (from active) 허용 (AC-9)
- `ended`에서 `Transition(StatusActive)` → `ErrInvalidTransition` (AC-10)
- `IsExpired(now)`: active(zero)는 항상 false, waiting은 ExpiresAt 경과 시 true (AC-13 보강)

### domain/invitation (단위)

- `New(serial, roomID)` → `ExpiresAt ≈ IssuedAt + InvitationTTL` (AC-2)
- `IsExpired(now)`: ExpiresAt 경과 판정

### infrastructure/memory — RoomSessionRepository

- `Create(New(NewID()))` → status `waiting`, 10분 후 ExpiresAt 반환 (AC-1)
- 동일 RoomID로 `Create` 재호출 → `roomsession.ErrAlreadyExists` (AC-5)
- `Get`: 만료 세션 → 삭제 + `roomsession.ErrExpired`, 재조회 시 `ErrNotFound`(잔존 없음 확인) (AC-11)
- `Get`: active 세션은 시간이 지나도 그대로 반환(만료 스킵) (AC-13)
- `Get(unknown)` → `roomsession.ErrNotFound`
- `Update` 후 active 세션 `ExpiresAt` zero 유지 (AC-7)
- **동시성**: 100 goroutine `Create`/`Get` 혼합 → `go test -race ./...` data race 없음 (AC-16, NFR-1)

### infrastructure/memory — InvitationRepository

- `Create(New(serial, roomID))` → 10분 후 ExpiresAt 반환 (AC-2)
- `ResolveBySerial(serial)` → 연결 invitation 반환 (AC-3)
- 동일 시리얼로 `Create` 재호출 → `invitation.ErrAlreadyExists` (AC-6)
- `ResolveBySerial("UNKNOWN")` → `invitation.ErrNotFound` (AC-4)
- `ResolveBySerial`: 만료 항목 → 삭제 + `invitation.ErrExpired`, 재조회 시 `ErrNotFound`(잔존 없음) (AC-12)
- `Delete(serial)` 후 `ResolveBySerial(serial)` → `ErrNotFound` (AC-14, AC-15)
- **동시성**: 100 goroutine `Create`/`ResolveBySerial`/`Delete` 혼합 → `go test -race ./...` data race 없음 (AC-16, NFR-1)

> 모든 동시성 검증은 `go test -race ./...`로 실행한다(CLAUDE.md 명령 표 기준).
