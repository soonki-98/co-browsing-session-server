# 연결 수립과 세션 활성화 — 기술 설계도

> 기획: [docs/specs/실시간-연결/연결_수립과_세션_활성화.md](../../specs/실시간-연결/연결_수립과_세션_활성화.md)

## Overview

고객과 상담원이 같은 시리얼 코드로 합류하면 양쪽 사이에 WebSocket 통로를 열고, 둘 다 모이면 세션을 `active`로 전이시킨다. 한쪽이 떠나면(명시 leave 또는 연결 끊김) 세션을 `ended`로 전이시키고 시리얼(Invitation)을 삭제해 재사용을 막으며, 남은 상대에게 이탈을 알린다.

`GET /ws?serial=...&role=...` 단일 엔드포인트가 진입점이다. WebSocket 업그레이드는 raw `http.ResponseWriter`를 요구해 huma 타입드 핸들러를 통과할 수 없으므로 gin 엔진에 직접 등록한다(`Register(engine *gin.Engine)`).

책임 분리:

- **트랜스포트 어댑터**(`interfaces/ws.Handler`): 업그레이드, 바이트 ↔ DTO 직렬화, read/write 펌프, 거부 상태 코드 변환만 담당한다.
- **유즈케이스 조율자**(`services/connection.Coordinator`): 휘발 Hub와 영속 상태(RoomSession + Invitation)를 묶어 Resolve/Join/Leave/Peer 흐름을 오케스트레이션한다.
- **휘발 라이브 연결**(`services/hub.Hub`): 룸 단위로 접속 중인 클라이언트 한 쌍을 관리한다(도메인/인프라 비참조).
- **영속 상태 서비스**(`services/roomsession.Service`): RoomSession 상태 전이(Activate/End)와 Invitation 삭제를 책임진다.
- **도메인 상태 머신**(`domain/roomsession`): `waiting → active → ended` 전이 규칙을 불변식으로 강제한다.

## Implementation Order

의존 순서(안쪽 → 바깥쪽). 안쪽이 먼저 존재해야 바깥쪽을 조립할 수 있다.

```
[domain]                                            [services]
roomsession (Status, Transition, sentinel)  ──┐
invitation  (Invitation, sentinel)          ──┤
serialnumber (SerialNumber)                 ──┤
roomsession.Repository (port)               ──┼──▶ roomsession.Service (Get/Activate/End)
invitation.Repository  (port)               ──┘            │
                                                            │
hub.Hub  (JoinRoom/LeaveRoom/GetPeer)  ─────────────┐      │
                                                     └──────┴──▶ connection.Coordinator
                                                                 (Resolve/Join/Leave/Peer)
                                                                          │
[interfaces]                                                              ▼
                                                              ws.Handler (GET /ws, pumps)
[app]                                                                     │
                                                                          ▼
                                                              app.New (composition root)
```

선행 의존성: 도메인 스토어(roomsession/invitation/serialnumber + 포트), Hub. 후행 의존성: 시그널링(offer/answer/ice-candidate)과 제어 이벤트 릴레이가 이 핸들러의 메시지 라우팅 위에서 동작한다(현재는 raw passthrough).

## Layer Mapping

| 책임 | 레이어 | 위치 |
|------|--------|------|
| `GET /ws` 업그레이드, read/write 펌프, 거부 상태 코드 변환, WS 메시지 DTO | interfaces | `internal/interfaces/ws/` |
| 접속/해제 유즈케이스 조율(Hub + 영속 상태), 유즈케이스 경계 에러 | services | `internal/services/connection/` |
| 휘발 라이브 룸(클라이언트 한 쌍) 관리 | services | `internal/services/hub/` |
| RoomSession 영속 상태 전이(Activate/End) + Invitation 삭제 | services | `internal/services/roomsession/` |
| 상태 머신 규칙, 엔티티, 타입드 식별자, sentinel 에러, 포트 | domain | `internal/domain/{roomsession,invitation,serialnumber}/` |
| 구체 타입 생성·주입·라우팅 조립 | app | `internal/app/app.go` |

의존 방향(depguard 강제): `interfaces/ws` → `services/{connection,hub}` → `domain`. `ws.Handler`는 `connection.Coordinator`와 `hub.Client`/`hub.Role`만 알고, 도메인 sentinel(`invitation.ErrNotFound` 등)은 직접 알지 않는다. 도메인 에러는 `Coordinator`가 유즈케이스 경계 에러(`ErrInvitationInvalid`/`ErrSessionEnded`)로 한 번 번역하고, `ws.Handler`가 다시 HTTP 상태 코드로 번역한다. Hub와 도메인은 식별자를 opaque `string`으로만 주고받아 도메인 타입이 트랜스포트로 새지 않는다.

## Data Structures

### interfaces/ws — WebSocket 메시지 DTO

```go
// internal/interfaces/ws/dto.go
package ws

// Message는 모든 WebSocket 메시지의 공통 래퍼다.
type Message struct {
    Type    string          `json:"type"`
    Payload json.RawMessage `json:"payload,omitempty"`
}

// ErrorPayload는 서버 → 클라이언트 error 메시지의 페이로드다.
type ErrorPayload struct {
    Code    string `json:"code"`
    Message string `json:"message"`
}

const (
    msgTypeOffer        = "offer"
    msgTypeAnswer       = "answer"
    msgTypeICECandidate = "ice-candidate"
    msgTypeControlEvent = "control-event"
    msgTypeLeave        = "leave"
    msgTypePeerJoined   = "peer-joined"
    msgTypePeerLeft     = "peer-left"
    msgTypeError        = "error"
)
```

`marshalMessage(messageType string, payload any) []byte`는 `{"type":...,"payload":...}`로 직렬화한다(payload가 nil이면 payload 필드 생략). 프로토콜 페이로드는 adapter 레이어 DTO로만 다루고 도메인 타입과 섞지 않는다.

### services/hub — Client & LiveRoom & Hub

```go
// internal/services/hub/hub.go
package hub

type Role string

const (
    RoleCustomer Role = "customer"
    RoleAgent    Role = "agent"
)

// Client는 WebSocket 연결 하나를 나타낸다.
// RoomID와 Serial은 opaque string으로만 다룬다 — Hub는 도메인 타입을 모른다.
type Client struct {
    Conn   *websocket.Conn
    Role   Role
    RoomID string      // = roomsession.RoomID 값
    Serial string      // disconnect 시 Invitation 삭제에 사용 (= invitation.Serial 값)
    Send   chan []byte // 이 클라이언트에게 보낼 메시지 채널 (버퍼드, cap 256)
}

// LiveRoom은 WS 연결 중인 클라이언트 한 쌍을 담는 휘발 컨테이너다.
type LiveRoom struct {
    ID       string  // = roomsession.RoomID 값
    Customer *Client // nil이면 아직 미접속
    Agent    *Client // nil이면 아직 미접속
}

// Hub는 모든 LiveRoom을 룸 단위로 관리하는 중앙 주소록이다.
type Hub struct {
    mutex     sync.RWMutex
    liveRooms map[string]*LiveRoom // key: RoomID
}

func NewHub() *Hub
```

## Interfaces / Contracts

### HTTP 엔드포인트

```
GET /ws?serial=AB3K7M&role=customer
GET /ws?serial=AB3K7M&role=agent

Upgrade: websocket
Connection: Upgrade

성공: WebSocket 프로토콜로 전환(101 Switching Protocols)
400 Bad Request:
  { "error": "missing serial or role parameter" }   // serial 또는 role 누락
  { "error": "role must be customer or agent" }      // role 값이 customer/agent가 아님
404 Not Found:
  { "error": "invitation not found or expired" }     // 존재하지 않음/만료/RoomSession not found·expired
410 Gone:
  { "error": "session already ended" }               // RoomSession.Status == ended
500 Internal Server Error:
  { "error": "failed to establish session" }         // 그 외 예기치 못한 에러
```

쿼리 파라미터 키는 `serial`(UX 용어). 핸들러는 raw string으로 받아 `Coordinator.Resolve`에 넘기고, 도메인 타입(`serialnumber.SerialNumber`) 변환은 services 레이어에서 일어난다.

### Coordinator 유즈케이스 메서드

```go
// Resolve: 업그레이드 전 시리얼 검증. 잘못된/만료 초대 → ErrInvitationInvalid,
//          이미 종료된 세션 → ErrSessionEnded. 성공 시 Target{RoomID, Serial}.
func (coordinator *Coordinator) Resolve(serial string) (Target, error)

// Join: Hub 등록. 양쪽이 모두 모이면 세션을 active로 전이. 반환은 알림 대상(대기 중이던 상대), 미접속이면 nil.
//       active 전이 실패는 비치명적 — peer는 그대로 반환하고 에러를 함께 돌려준다(호출자가 로깅).
func (coordinator *Coordinator) Join(client *hub.Client) (peer *hub.Client, err error)

// Leave: Hub 제거. 첫 disconnect라면 세션 ended 전이 + Invitation 삭제. 반환은 알림 대상(상대), 없으면 nil.
func (coordinator *Coordinator) Leave(client *hub.Client) (peer *hub.Client, err error)

// Peer: 메시지 릴레이 대상(상대). 없으면 nil.
func (coordinator *Coordinator) Peer(client *hub.Client) *hub.Client
```

### Hub 계약

```go
// JoinRoom: 클라이언트를 LiveRoom에 추가(없으면 생성). 동일 role이 이미 접속 중이면 기존 Conn.Close() 후 교체.
//           반환은 상대 role 클라이언트, 미접속이면 nil.
func (hub *Hub) JoinRoom(roomID string, client *Client) (peer *Client)

func (hub *Hub) LeaveRoom(client *Client) (peer *Client)

func (hub *Hub) GetRoom(roomID string) *LiveRoom
func (hub *Hub) GetPeer(client *Client) *Client
```

### roomsession.Service 전이 계약

```go
// Activate: 양쪽 접속 순간 active로 전이. 이미 active/ended(ErrInvalidTransition)면 멱등하게 무시(nil 반환).

func (service *Service) End(roomID roomsession.RoomID, serial serialnumber.SerialNumber) error
```

## Behavior

### 세션 상태 머신 (대기 → 활성 → 종료)

도메인 `roomsession.Status.CanTransitionTo`가 강제하는 단방향 전이:

```
            Activate (양쪽 합류)        End (첫 이탈)
  ┌──────────┐                ┌─────────┐                ┌────────┐
  │ waiting  │ ─────────────▶ │ active  │ ─────────────▶ │ ended  │
  │(생성 직후)│                │ ExpiresAt│                │(불가역) │
  │ ExpiresAt│ ─────────────────────────────────────────▶│        │
  │ =now+10m │        End (한쪽만 있는 동안 이탈)            └────────┘
  └──────────┘
      │
      │ TTL 10분 경과 → 리포지토리 read-on-check가 삭제 + ErrExpired
      ▼
   (소멸: 합류 불가)
```

규칙:

- `waiting → active`, `waiting → ended`, `active → ended`만 허용. `ended`에서는 어떤 전이도 불가(`CanTransitionTo`가 false → `ErrInvalidTransition`).
- `active`로 진입하면 `Transition`이 `ExpiresAt`을 zero로 만들어 무기한 유지한다(합류 후엔 TTL 만료로 끊기지 않음).
- TTL 만료는 별도 스위퍼가 아니라 **read-on-check**다: `Repository.Get`/`ResolveBySerial`이 만료 항목을 발견하면 삭제 후 `ErrExpired`를 반환한다.

### 연결 수립 흐름 (handleUpgrade)

```
1. query param 검증
   - serial == "" || role == ""              → 400 "missing serial or role parameter"
   - role != customer && role != agent        → 400 "role must be customer or agent"

2. target, err := coordinator.Resolve(serial)
   - errors.Is(err, ErrInvitationInvalid)     → 404 "invitation not found or expired"
   - errors.Is(err, ErrSessionEnded)          → 410 "session already ended"
   - 그 외                                     → 500 "failed to establish session"

   Resolve 내부:
     a. invitationRepository.ResolveBySerial → ErrNotFound/ErrExpired면 ErrInvitationInvalid
     b. roomSessionService.Get(RoomID)       → ErrNotFound/ErrExpired면 ErrInvitationInvalid
     c. roomSession.Status == ended          → ErrSessionEnded
     (불필요한 업그레이드를 막는 가벼운 사전 검증)

3. conn, err := upgrader.Upgrade(...)
   - 실패 시 gorilla가 응답을 이미 처리 → return

4. client := &hub.Client{Conn, Role(role), target.RoomID, target.Serial, Send: make(chan []byte, 256)}

5. peer, err := coordinator.Join(client)
   - err != nil → log.Printf("join room ...")  (비치명적, 연결 유지)
   - peer != nil (양쪽 모인 첫 순간) → trySend(peer, marshalMessage("peer-joined", nil))

6. done := make(chan struct{})
   go writePump(client, done)
   go readPump(client, done)
```

### readPump (읽기 루프)

```
defer cleanup(client, done)
loop:
  _, rawMessage, err := conn.ReadMessage()
  err != nil → return                                    // close/timeout/네트워크 오류 → defer cleanup
  json.Unmarshal(rawMessage, &Message) 실패 → sendError("MALFORMED", "invalid message format"); continue
  switch Type:
    offer | answer | ice-candidate | control-event
        → peer := coordinator.Peer(client); peer != nil이면 trySend(peer, rawMessage)  // raw passthrough
          (TODO step5/6: role 검증 + services/signaling·relay로 교체)
    leave  → return                                       // defer cleanup이 정상 이탈 처리
    default → sendError("UNKNOWN_TYPE", "unknown message type: "+Type)  // 연결 유지
```

### writePump (쓰기 루프)

```
defer conn.Close()
select:
  message := <-client.Send → WriteMessage(TextMessage, message); 실패 시 return
  <-done                   → return     // 상대 정리/연결 종료 시 루프 탈출
```

### cleanup (disconnect 처리)

```
close(done)                              // writePump 깨움
peer, err := coordinator.Leave(client)   // Hub 제거 + 첫 disconnect면 세션 ended + Invitation 삭제
conn.Close()
err != nil → log.Printf("leave room ...")
peer != nil → trySend(peer, marshalMessage("peer-left", nil))
// peer == nil이면 이미 종료됐거나 단독 접속 후 이탈 — 추가 처리 없음
```

이탈 사유(명시 leave vs 네트워크 끊김)는 동일하게 cleanup으로 수렴한다 — leave는 `return`으로, 네트워크 끊김은 `ReadMessage` 에러로 루프를 빠져나오고 둘 다 `defer cleanup`을 탄다.

### 종료 시 Invitation 삭제 (roomsession.Service.End)

```
rs, err := Get(roomID)
  err == ErrNotFound || ErrExpired → invRepo.Delete(serial) (best-effort); return nil
  err != nil (그 외)               → wrap & return
rs.Transition(ended)
  성공                             → roomSessionRepository.Update(rs)
  ErrInvalidTransition (이미 ended) → 무시 (Invitation만 삭제)
  그 외 에러                        → wrap & return
invRepo.Delete(serial)            // best-effort, defense in depth
return nil
```

세션을 ended로 만드는 것과 Invitation을 삭제하는 두 작업을 함께 수행해, 종료된 세션의 시리얼이 재합류에 쓰일 수 없게 한다(1회용 보장).

### sentinel 에러 번역 체인

```
domain                          services(connection)        interfaces(ws)
invitation.ErrNotFound  ─┐
invitation.ErrExpired    ├──▶ connection.ErrInvitationInvalid ──▶ 404
roomsession.ErrNotFound  │
roomsession.ErrExpired  ─┘
roomsession.StatusEnded ─────▶ connection.ErrSessionEnded     ──▶ 410
roomsession.ErrInvalidTransition ─▶ (Activate/End이 멱등하게 흡수)
(그 외)                  ─────▶ fmt.Errorf("...: %w", err)     ──▶ 500
```

각 레이어 경계에서 한 번씩 그 레이어의 언어로 번역한다. interfaces는 도메인 sentinel을 직접 알지 않는다.

### 동시성 설계

- 클라이언트마다 read 펌프와 write 펌프를 별도 goroutine으로 돌려 읽기/쓰기를 분리한다(한쪽 처리 지연이 다른 쪽을 막지 않음, NFR-2/AC-10).
- `Send`는 버퍼드 채널(cap 256). `trySend`는 비차단(`select ... default`)으로, 채널이 가득 찬 슬로우 클라이언트는 메시지를 드롭하지 않고 `Conn.Close()`로 연결을 끊어 전체 흐름을 보호한다.
- `Hub`는 `sync.RWMutex`로 `liveRooms` 맵을 보호한다(NFR-1). 룸별 격리는 RoomID 키로 자연히 보장된다.
- `done` 채널로 cleanup → writePump 종료를 신호한다(goroutine 누수 방지).

### 기능 요구사항(FR)

| FR | 구현 위치 |

| FR-1 합류 시 역할+시리얼 수신 | `ws.handleUpgrade` query param `serial`/`role` |

### 비즈니스 룰 / 비기능(NFR)

| 룰/NFR | 구현 위치 |
|--------|-----------|
| 시리얼 1회용 | `Service.End` Invitation 삭제 + `Resolve` ended → `ErrSessionEnded` |
