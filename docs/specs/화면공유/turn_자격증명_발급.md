# TURN 자격증명 발급 — 기획 요구사항

## 배경 / 목적

상담사와 고객의 화면 공유는 기본적으로 두 브라우저가 서로 직접 연결되는 방식(P2P)으로 동작한다. 그러나 일부 네트워크 환경(엄격한 방화벽, 대칭형 NAT 등)에서는 직접 연결이 맺어지지 않아 화면이 보이지 않는 문제가 생긴다. 이때 중계 서버(TURN)를 경유하면 연결을 살릴 수 있다. 이 기능은 클라이언트가 그 중계 서버에 접속할 때 사용할 **단기 접속 자격증명**을 발급해, 직접 연결이 실패하더라도 화면 공유가 폴백 경로로 이어지도록 한다.

## 용어

- **P2P(직접 연결)**: 고객과 상담사의 브라우저가 중간 서버를 거치지 않고 서로 직접 미디어를 주고받는 연결 방식. 기본 경로다.
- **TURN(중계 서버)**: P2P 직접 연결이 불가능할 때 두 브라우저 사이의 미디어를 대신 전달해 주는 중계 서버. 직접 연결이 실패할 때만 쓰이는 폴백 경로다.
- **TURN 접속 자격증명**: 클라이언트가 TURN 중계 서버에 접속할 수 있게 해 주는 접속 정보(사용자명·비밀번호 등)와 접속 대상 서버 주소, 그리고 그 유효 기간으로 구성된다. 영구적이지 않고 일정 시간만 유효하다.
- **유효 기간(TTL)**: 발급된 자격증명이 사용 가능한 시간. 이 시간이 지나면 자격증명은 만료되어 더 이상 중계 서버 접속에 쓸 수 없다.

## 사용자 스토리 / 시나리오

- 고객으로서, 내 네트워크가 직접 연결을 막더라도 상담사에게 화면이 보이도록, 중계 서버를 경유한 폴백 연결을 맺고 싶다.
- 상담사로서, 고객의 네트워크 환경과 무관하게 화면 공유가 끊기지 않도록, 직접 연결 실패 시 자동으로 중계 경로로 이어지길 원한다.

주요 흐름(클라이언트 관점):

```
1. 화면 공유 연결을 준비하는 클라이언트가 TURN 접속 자격증명을 요청한다.
2. 서버가 단기간만 유효한 접속 자격증명(접속 정보 + 중계 서버 주소 + 유효 기간)을 발급한다.
3. 클라이언트는 먼저 P2P 직접 연결을 시도한다.
4-a. 직접 연결이 성공하면 중계 서버는 사용되지 않는다.
4-b. 직접 연결이 실패하면 받은 자격증명으로 중계 서버에 접속해 폴백 경로로 화면 공유를 이어간다.
5. 유효 기간이 지나면 그 자격증명은 만료되어 더는 쓸 수 없다.
```

## 기능 요구사항 (FR)

- FR-1. 시스템은 클라이언트의 요청에 대해 TURN 중계 서버 접속에 필요한 자격증명을 발급해야 한다.
- FR-2. 발급되는 자격증명은 접속 정보(사용자명·비밀번호), 접속할 중계 서버 주소 목록, 그리고 유효 기간을 함께 포함해야 한다.
- FR-3. 접속할 중계 서버 주소는 하나 이상 제공되어야 한다.
- FR-4. 발급된 자격증명에는 명시적인 유효 기간이 포함되어야 하며, 그 기간 동안만 유효해야 한다.
- FR-5. 유효 기간이 지난 자격증명은 만료되어 중계 서버 접속에 사용할 수 없어야 한다.
- FR-6. 자격증명 발급은 화면 공유의 다른 단계(세션 생성, 시그널링, 제어 이벤트 중계)와 무관하게 독립적으로 요청·발급될 수 있어야 한다.
- FR-7. (MVP) 자격증명 발급 요청에는 별도의 사용자 인증을 요구하지 않는다.

## 규칙 / 제약 (비즈니스 룰)

- 중계 서버는 **폴백 전용**이다. 직접 연결이 성공하면 발급된 자격증명은 실제로 사용되지 않으며, 이는 정상 동작이다.
- 자격증명은 **단기성**이다. 영구 자격증명을 발급하지 않으며, 매 요청마다 그 시점 기준의 유효 기간을 갖는 새 자격증명을 발급한다.
- 자격증명의 유효 기간은 발급 시점부터 계산되며, 같은 시각에 발급된 자격증명들은 동일한 만료 시점을 향한다. 서로 다른 시점(특히 발급 간격이 충분히 벌어진 경우)의 요청은 서로 다른 자격증명을 받을 수 있다.
- (MVP) 운영 환경에 실제 중계 서버가 구성되어 있지 않은 경우에도 발급 요청은 정상적으로 자격증명을 반환한다. 다만 실제 중계 서버가 없으면 폴백 연결 자체는 성립하지 않는다 — 이는 직접 연결이 성공하는 한 화면 공유에 영향을 주지 않으므로 MVP에서 허용되는 동작이다.

## 비기능 요구사항 (NFR)

- NFR-1. (보안) 자격증명은 단기간만 유효해야 하며, 유효 기간이 지나면 더 이상 중계 서버 접속에 쓸 수 없어야 한다. 장기·영구 자격증명을 노출하지 않는다.
- NFR-2. (보안) 발급에 쓰이는 비밀 키 등 민감 정보는 외부로 노출하거나 로그에 남기지 않는다. 발급된 비밀번호 등 자격증명 값 자체도 로그에 남기지 않는다.
- NFR-3. (운영) 중계 서버 주소와 발급에 필요한 비밀 정보는 운영 환경별로 설정으로 분리·재구성할 수 있어야 하며, 운영 배포 전에는 개발용 기본값이 그대로 쓰이지 않도록 한다.
- NFR-4. (가용성) 자격증명 발급은 진행 중인 세션 상태나 실시간 연결과 독립적으로 동작해, 다른 기능의 부하나 장애가 발급에 영향을 주지 않아야 한다.

## 인수 조건 (Acceptance Criteria)

- [ ] AC-1. (When) 클라이언트가 TURN 자격증명을 요청하면 (Then) 접속 정보(사용자명·비밀번호), 중계 서버 주소 목록, 유효 기간이 모두 포함된 자격증명을 정상적으로 받는다.
- [ ] AC-2. (Then) 반환된 자격증명에는 중계 서버 주소가 하나 이상 포함되어 있다.
- [ ] AC-3. (Then) 반환된 자격증명에는 명시적인 유효 기간이 포함되어 있다.
- [ ] AC-4. (Given) 유효 기간이 지난 뒤 (When) 같은 자격증명으로 중계 서버 접속을 시도하면 (Then) 만료되어 접속에 사용할 수 없다.
- [ ] AC-5. (Given) 충분한 시간 간격을 두고 (When) 두 번 연속으로 자격증명을 요청하면 (Then) 두 응답의 자격증명(특히 만료 시점)이 서로 다를 수 있다.
- [ ] AC-6. (Given) 별도의 인증 정보 없이 (When) 자격증명을 요청해도 (Then) MVP에서는 발급이 정상적으로 이루어진다.
- [ ] AC-7. (Given) 직접 연결(P2P)이 성공한 상황에서 (Then) 발급된 자격증명은 사용되지 않아도 화면 공유는 정상 동작한다(중계 서버는 폴백 전용임).
- [ ] AC-8. (Given) 실제 중계 서버가 구성되지 않은 환경에서 (When) 자격증명을 요청하면 (Then) 발급 자체는 정상적으로 응답된다(폴백 연결 성립 여부와 무관).
