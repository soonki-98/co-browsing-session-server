# 룸 세션과 초대 저장 — 기획 요구사항

## 배경 / 목적

고객 지원(CS) co-browsing은 고객이 발급받은 시리얼 코드를 상담원이 입력해 한 화면을 함께 보는 것에서 시작한다. 이를 위해 서버는 "지금 진행 중인 화면 공유"의 상태를 어딘가에 기록하고, 고객이 받은 시리얼 코드로 그 화면 공유를 다시 찾아낼 수 있어야 한다. 이 문서는 그 두 가지 — 화면 공유 한 건의 진행 상태(룸 세션)와 시리얼 코드로 그 화면 공유를 찾아가는 연결고리(초대) — 를 만들고, 진행시키고, 만료/종료시키는 규칙을 정의한다. 이후 모든 연결·중계 기능은 여기에 기록된 상태 위에서 동작한다.

## 용어

- **시리얼 코드**: 고객이 세션 시작 시 발급받는 6자리 코드. 고객이 상담원에게 전달하고, 상담원이 콘솔에 입력해 같은 화면 공유에 합류하는 데 쓰인다.
- **룸 세션**: 화면 공유 한 건의 진행 상태를 나타내는 단위. 대기 → 진행 → 종료의 생애주기를 가진다.
- **초대**: 시리얼 코드와 룸 세션을 잇는 연결고리. 고객이 받은 시리얼 코드로 어떤 룸 세션에 합류해야 하는지를 알려준다.
- **고객 / 상담원**: 화면 공유의 양쪽 참여자. 고객이 자기 화면을 공유하고, 상담원이 그 화면을 보며 안내한다.
- **대기 / 진행 / 종료**: 룸 세션의 세 가지 상태. 양쪽이 모두 합류하기 전이 대기, 양쪽이 합류해 화면 공유가 진행 중이면 진행, 끝나면 종료다.

## 사용자 스토리 / 시나리오

- 고객으로서 화면 공유를 시작하기 위해 세션 시작을 요청하면, 시리얼 코드 하나와 그에 대응하는 화면 공유 한 건이 새로 만들어진다.
- 상담원으로서 고객에게 전달받은 시리얼 코드를 입력하면, 그 코드에 연결된 화면 공유를 찾아 합류할 수 있다.
- 고객/상담원으로서 양쪽이 모두 합류하면, 그 화면 공유는 대기에서 진행 상태로 바뀐다.
- 고객/상담원으로서 화면 공유를 끝내면(혹은 한쪽이 이탈하면), 그 화면 공유는 종료 상태가 되고 시리얼 코드로 더 이상 찾을 수 없게 된다.
- 고객으로서 시리얼 코드를 받고 제때 화면 공유를 시작하지 못하면, 일정 시간이 지난 뒤 그 코드와 화면 공유는 자동으로 무효가 된다.

```
세션 시작 요청 ──▶ 시리얼 코드 발급 + 룸 세션 생성(대기)
                      │
   상담원이 시리얼 코드로 초대를 조회 ──▶ 연결된 룸 세션을 찾음
                      │
        양쪽이 모두 합류 ──▶ 룸 세션 진행
                      │
   한쪽 이탈/종료 ──▶ 룸 세션 종료 + 초대 제거
```

## 기능 요구사항 (FR)

- FR-1. 시스템은 새 화면 공유 한 건을 만들 때, 그 화면 공유를 다른 화면 공유와 구별되는 고유 식별로 만들고 처음 상태를 "대기"로 둔다.
- FR-2. 시스템은 새 화면 공유를 만들 때, 그것을 가리키는 초대를 하나의 시리얼 코드에 연결해 함께 등록한다.
- FR-3. 시스템은 시리얼 코드를 받아, 그 코드에 연결된 화면 공유를 찾아 돌려줄 수 있어야 한다.
- FR-4. 시스템은 알 수 없는(등록된 적 없는) 시리얼 코드로 조회하면, 연결된 화면 공유가 없음을 알린다.
- FR-5. 시스템은 양쪽(고객·상담원)이 모두 합류하면 화면 공유를 "대기"에서 "진행"으로 바꾼다.
- FR-6. 시스템은 화면 공유가 끝나거나 한쪽이 이탈하면 화면 공유를 "종료"로 바꾼다.
- FR-7. 시스템은 화면 공유가 종료되면, 그 화면 공유를 가리키던 초대를 제거해 같은 시리얼 코드로 더 이상 합류할 수 없게 한다.
- FR-8. 시스템은 허용되지 않는 상태 변경(예: 종료된 화면 공유를 다시 진행으로 되돌리기)을 거부한다.
- FR-9. 시스템은 발급 후 정해진 시간 안에 진행으로 이어지지 못한 시리얼 코드/화면 공유를 만료시켜, 더 이상 합류·진행에 쓰이지 못하게 한다.
- FR-10. 시스템은 만료된 시리얼 코드로 조회하거나 만료된 화면 공유를 조회하면, 만료되었음을 알리고 그 만료된 항목을 더 이상 남겨두지 않는다.
- FR-11. 시스템은 이미 사용 중인 동일 식별/동일 시리얼 코드로 화면 공유나 초대를 중복 생성하려는 시도를 거부한다.

## 규칙 / 제약 (비즈니스 룰)

- 룸 세션의 상태는 "대기 → 진행 → 종료" 방향으로만 흐른다.
  - 대기에서 진행으로 갈 수 있다(양쪽 합류).
  - 대기에서 종료로 바로 갈 수 있다(합류 전 만료 직전 종료 또는 비정상 종료).
  - 진행에서 종료로 갈 수 있다(정상 종료/이탈).
  - 그 외의 변경(종료 → 진행, 진행 → 대기, 종료 → 대기 등)은 허용되지 않는다.
- 만료 정책:
  - 화면 공유는 만들어진 시점부터 **10분** 안에 진행 상태로 이어지지 못하면 만료된다.
  - 화면 공유가 "진행" 상태가 되면 더 이상 시간 만료를 적용하지 않는다(진행 중인 상담은 시간으로 끊지 않는다).
  - 시리얼 코드(초대)도 발급 시점부터 **10분**이 지나면 만료된다.
- 만료 처리 시점: 만료는 그 항목을 **조회하는 순간** 판정한다. 조회 시 만료가 확인되면 만료되었음을 알리는 동시에 그 항목을 제거한다(만료된 채로 남겨두지 않는다).
- 초대에는 별도의 상태 개념이 없다 — 존재하면 유효하고, 만료되거나 제거되면 무효다.
- 초대 제거는 화면 공유 종료 흐름에서 일어난다. 한 번 종료된 화면 공유의 시리얼 코드는 재사용되지 않는다.
- 한 시리얼 코드는 정확히 하나의 화면 공유를 가리킨다(중복 연결 불가).

## 비기능 요구사항 (NFR)

- NFR-1. 여러 고객·상담원의 화면 공유가 동시에 생성·조회·종료되어도 서로의 상태가 뒤섞이거나 손상되지 않고 안전하게 동작한다.
- NFR-2. 시리얼 코드는 민감 정보로 취급한다 — 운영 기록(로그)에 그대로 남기지 않는다.
- NFR-3. 화면 공유와 초대 상태는 서비스 운영 중 즉시 조회·갱신 가능한 빠른 응답을 전제로 한다(별도 외부 저장소 없이 운영 중 보관, MVP 범위).
- NFR-4. 만료 판정은 별도의 주기적 정리 작업에 의존하지 않고, 조회 시점에 일관되게 적용된다.

## 인수 조건 (Acceptance Criteria)

- [ ] AC-1. (Given 세션 시작) (When 새 화면 공유를 만든다) (Then 상태가 "대기"이고, 만들어진 시점부터 10분 뒤를 만료 시각으로 갖는 화면 공유가 생성된다)
- [ ] AC-2. (Given 새 화면 공유) (When 그것을 가리키는 초대를 시리얼 코드에 연결해 등록한다) (Then 발급 시점부터 10분 뒤를 만료 시각으로 갖는 초대가 만들어진다)
- [ ] AC-3. (Given 등록된 초대) (When 그 시리얼 코드로 조회한다) (Then 연결된 화면 공유가 반환된다)
- [ ] AC-4. (Given 등록된 적 없는 시리얼 코드) (When 조회한다) (Then 연결된 화면 공유가 없음을 알린다)
- [ ] AC-5. (Given 같은 식별의 화면 공유가 이미 존재) (When 동일 식별로 다시 생성한다) (Then 중복 생성이 거부된다)
- [ ] AC-6. (Given 같은 시리얼 코드의 초대가 이미 존재) (When 동일 시리얼 코드로 다시 등록한다) (Then 중복 등록이 거부된다)
- [ ] AC-7. (Given 대기 상태의 화면 공유) (When 양쪽 합류로 진행으로 바꾼다) (Then 상태가 "진행"이 되고 더 이상 시간 만료가 적용되지 않는다)
- [ ] AC-8. (Given 대기 상태의 화면 공유) (When 종료로 바꾼다) (Then 대기에서 종료로의 변경이 허용된다)
- [ ] AC-9. (Given 진행 상태의 화면 공유) (When 종료로 바꾼다) (Then 진행에서 종료로의 변경이 허용된다)
- [ ] AC-10. (Given 종료된 화면 공유) (When 다시 진행으로 되돌리려 한다) (Then 허용되지 않는 상태 변경으로 거부된다)
- [ ] AC-11. (Given 만료 시각이 지난 화면 공유) (When 그 화면 공유를 조회한다) (Then 만료되었음을 알리고, 해당 화면 공유는 더 이상 남아 있지 않는다)
- [ ] AC-12. (Given 만료 시각이 지난 초대) (When 그 시리얼 코드로 조회한다) (Then 만료되었음을 알리고, 해당 초대는 더 이상 남아 있지 않는다)
- [ ] AC-13. (Given 진행 상태의 화면 공유) (When 시간이 충분히 지난 뒤 조회한다) (Then 시간 만료로 사라지지 않고 그대로 조회된다)
- [ ] AC-14. (Given 등록된 초대) (When 그 초대를 제거한 뒤 같은 시리얼 코드로 조회한다) (Then 연결된 화면 공유가 없음을 알린다)
- [ ] AC-15. (Given 화면 공유 종료 흐름) (When 화면 공유가 종료된다) (Then 그 화면 공유를 가리키던 초대가 제거되어 같은 시리얼 코드로 더 이상 합류할 수 없다)
- [ ] AC-16. (Given 다수의 화면 공유·초대가 동시에) (When 여러 참여자가 동시에 생성·조회·제거를 수행한다) (Then 상태 손상이나 충돌 없이 각 화면 공유·초대가 일관되게 처리된다)
