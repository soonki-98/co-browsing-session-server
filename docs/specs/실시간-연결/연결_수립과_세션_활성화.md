# 연결 수립과 세션 활성화 — 기획 요구사항

## 배경 / 목적

고객이 발급받은 시리얼 코드는 상담원과 만나기 위한 약속표다. 고객과 상담원이 같은 시리얼로 합류하면 양쪽 사이에 실시간 연결이 열려야 하고, 둘 다 모인 순간부터 세션이 "진행 중"으로 바뀌어 화면 공유와 원격 제어가 시작될 수 있어야 한다. 또한 누군가 자리를 뜨면 세션은 즉시 끝나야 하며, 한 번 쓴 시리얼은 다시 쓸 수 없어야 한다 — 끝난 만남에 제3자가 끼어들거나, 종료된 세션이 되살아나는 일을 막기 위함이다.

## 용어

- **시리얼 코드**: 고객이 세션을 시작할 때 발급받는 6자리 코드. 고객이 상담원에게 전달해, 두 사람이 같은 세션에 모이는 데 쓰는 1회용 합류 열쇠.
- **세션**: 한 시리얼 코드로 묶이는 고객–상담원 만남의 단위. 대기 → 활성 → 종료의 상태를 가진다.
- **고객 / 상담원**: 세션에 합류하는 두 역할. 고객은 화면을 공유하는 쪽, 상담원은 그 화면을 보고 안내·제어하는 쪽이다.
- **실시간 연결**: 합류한 참가자와 서버 사이에 유지되는 양방향 통로. 이 통로가 열려 있는 동안 참가자는 "접속 중"으로 간주된다.
- **상대 합류 알림 / 상대 이탈 알림**: 한쪽 참가자에게 다른 쪽이 막 들어왔거나 막 나갔음을 전하는 신호.

## 사용자 스토리 / 시나리오

- 고객으로서, 발급받은 시리얼로 세션에 합류해 상담원이 들어오기를 기다리고 싶다.
- 상담원으로서, 고객이 알려준 시리얼로 같은 세션에 합류해 곧바로 화면 공유를 시작하고 싶다.
- 고객/상담원으로서, 상대가 들어오거나 나갔을 때 그 사실을 즉시 알고 싶다.
- 운영자로서, 끝난 세션의 시리얼이 재사용되어 엉뚱한 연결이 맺어지는 일이 없기를 바란다.

주요 흐름:

```
1. 고객이 자신의 역할과 시리얼로 합류를 요청한다
     → 시리얼이 유효하면 실시간 연결이 열리고, 세션은 아직 "대기" 상태로 상담원을 기다린다
2. 상담원이 같은 시리얼로 합류를 요청한다
     → 실시간 연결이 열리고, 양쪽이 모였으므로 세션이 "활성" 상태로 바뀐다
     → 먼저 와 있던 고객은 "상대 합류 알림"을 받는다
3. 한쪽이 떠난다 (스스로 나가거나, 연결이 끊긴다)
     → 세션이 "종료" 상태가 되고, 남은 쪽은 "상대 이탈 알림"을 받는다
     → 그 시리얼은 더 이상 합류에 쓸 수 없게 된다
```

## 기능 요구사항 (FR)

- **FR-1.** 시스템은 합류 요청 시 합류할 역할(고객/상담원)과 시리얼 코드를 함께 받아야 한다.
- **FR-2.** 시스템은 시리얼 코드가 유효한 세션을 가리킬 때에만 실시간 연결을 열어야 한다.
- **FR-3.** 시스템은 참가자가 합류해도 상대가 아직 없으면 세션을 "대기" 상태로 유지해야 한다.
- **FR-4.** 시스템은 고객과 상담원 양쪽이 모두 합류한 순간 세션을 "활성" 상태로 전환해야 한다.
- **FR-5.** 시스템은 두 번째 참가자가 합류한 순간, 먼저 합류해 있던 참가자에게 "상대 합류 알림"을 보내야 한다.
- **FR-6.** 시스템은 합류한 참가자가 스스로 떠나기를 요청하면 그 연결을 종료해야 한다.
- **FR-7.** 시스템은 참가자의 연결이 어떤 이유로든(스스로 떠남 또는 비정상 끊김) 끊기면 해당 세션을 "종료" 상태로 전환해야 한다.
- **FR-8.** 시스템은 한쪽이 떠나 세션이 종료될 때, 남아 있는 상대 참가자에게 "상대 이탈 알림"을 보내야 한다.
- **FR-9.** 시스템은 세션이 종료되면 그 세션을 가리키던 시리얼 코드를 더 이상 합류에 쓸 수 없게 만들어야 한다.
- **FR-10.** 시스템은 합류한 두 참가자 사이의 실시간 대화(화면 공유 협의·제어 신호 등)가 양방향으로 오갈 수 있는 통로를 제공해야 한다.
- **FR-11.** 시스템은 참가자가 약속된 형식에 맞지 않거나 알 수 없는 종류의 메시지를 보내더라도 연결을 끊지 않고, 해당 참가자에게 오류 안내를 돌려보내야 한다.

## 규칙 / 제약 (비즈니스 룰)

- **시리얼은 1회용이다.** 한 세션이 종료되면 그 시리얼로는 다시 합류할 수 없다. 종료된 세션에 같은 시리얼로 합류를 시도하면 거부된다.
- **세션 상태는 한 방향으로만 흐른다:** 대기 → 활성 → 종료. 이미 종료된 세션은 다시 활성화되지 않는다.
- **"활성"은 양쪽이 모두 있을 때에만 성립한다.** 한 명만 있는 동안은 계속 "대기"다.
- **세션 종료의 방아쇠는 한쪽의 첫 이탈이다.** 두 사람 중 누구든 먼저 떠나면 세션은 끝나고, 남은 한 사람도 더 이상 그 세션을 이어갈 수 없다.
- **이탈의 사유는 종료 처리에 영향을 주지 않는다.** 스스로 "떠나기"를 요청했든, 네트워크가 끊겨 비정상 종료됐든, 동일하게 세션이 종료되고 상대에게 이탈이 통지된다.
- **유효하지 않은 합류 시도는 사유별로 구분되어 거부된다:**
  - 역할 또는 시리얼이 빠진 요청 → 잘못된 요청으로 거부.
  - 존재하지 않거나 이미 만료된 시리얼 → "찾을 수 없음"으로 거부.
  - 이미 종료된 세션의 시리얼 → "이미 끝난 세션"으로 거부.
- **만료된 합류 기회는 자동으로 무효가 된다.** 시리얼은 발급 후 일정 시간(10분) 동안만 합류에 쓸 수 있으며, 그 시간이 지나면 사용되지 않았더라도 더 이상 합류할 수 없다.
- **잘못된 메시지가 연결을 깨지 않는다.** 형식 오류나 알 수 없는 종류의 메시지는 오류 안내만 돌려보내고 연결은 유지한다. 단, 참가자가 명시적으로 "떠나기"를 보낸 경우는 정상 이탈로 처리한다.

## 비기능 요구사항 (NFR)

- **NFR-1.** 여러 세션이 동시에 진행되어도 서로 간섭 없이 안전하게 동작해야 한다. 한 세션의 합류·이탈이 다른 세션에 영향을 주지 않는다.
- **NFR-2.** 한 참가자가 메시지를 받아 처리하느라 느려지더라도, 같은 세션의 다른 참가자가 보내고 받는 흐름이 그 때문에 멈춰서는 안 된다.
- **NFR-3.** 시리얼 코드는 합류를 식별하는 민감한 값이므로, 운영 로그에 그대로 남기지 않는다.
- **NFR-4.** 상대의 합류·이탈은 사용자가 체감할 수 있을 만큼 즉시 통지되어야 한다(눈에 띄는 지연 없이).

## 인수 조건 (Acceptance Criteria)

- [ ] **AC-1.** (Given 존재하지 않는 시리얼) (When 그 시리얼로 합류를 시도한다) (Then 연결이 열리지 않고 "찾을 수 없음"으로 거부된다)
- [ ] **AC-2.** (Given 역할 또는 시리얼이 빠진 합류 요청) (When 합류를 시도한다) (Then 잘못된 요청으로 거부된다)
- [ ] **AC-3.** (Given 유효한 시리얼) (When 고객이 합류한다) (Then 실시간 연결이 열리고, 상대가 아직 없으므로 세션은 "대기" 상태를 유지한다)
- [ ] **AC-4.** (Given 고객이 먼저 합류해 대기 중) (When 상담원이 같은 시리얼로 합류한다) (Then 세션이 "활성" 상태로 바뀌고, 먼저 와 있던 고객은 "상대 합류 알림"을 받는다)
- [ ] **AC-5.** (Given 고객과 상담원이 모두 합류한 활성 세션) (When 상담원이 "떠나기"를 보낸다) (Then 세션이 "종료" 상태가 되고, 고객은 "상대 이탈 알림"을 받는다)
- [ ] **AC-6.** (Given 고객과 상담원이 모두 합류한 활성 세션) (When 한쪽의 연결이 비정상적으로 끊긴다) (Then 스스로 떠난 경우와 동일하게 세션이 "종료"되고, 남은 쪽이 "상대 이탈 알림"을 받는다)
- [ ] **AC-7.** (Given 한 번 종료된 세션) (When 같은 시리얼로 다시 합류를 시도한다) (Then 합류가 거부되어 연결이 열리지 않는다)
- [ ] **AC-8.** (Given 발급 후 10분이 지나도록 사용되지 않은 시리얼) (When 그 시리얼로 합류를 시도한다) (Then 만료되어 합류가 거부된다)
- [ ] **AC-9.** (Given 합류해 연결이 열린 참가자) (When 약속된 형식에 맞지 않거나 알 수 없는 종류의 메시지를 보낸다) (Then 연결은 유지된 채 해당 참가자에게 오류 안내가 돌아온다)
- [ ] **AC-10.** (Given 같은 세션에 모인 두 참가자) (When 한쪽이 메시지를 보낸다) (Then 다른 쪽이 그 메시지를 받을 수 있고, 한쪽의 처리 지연이 다른 쪽의 흐름을 멈추지 않는다)
