# 시리얼로 룸 생성 — 기획 요구사항

## 배경 / 목적

고객 지원(CS) 상황에서 상담원과 고객이 화면을 함께 보려면, 먼저 두 사람이 합류할 "공동 작업 공간"이 만들어져야 한다. 이 공간(룸 세션)은 한 번의 요청으로 생성되고, 고객에게 구두/복사로 전달할 수 있는 짧은 시리얼 번호로 식별된다. 상담원은 별도의 사전 설정 없이 즉시 새 세션을 열고, 고객에게 건넬 시리얼 번호와 그 번호가 언제까지 유효한지를 한 번에 돌려받을 수 있어야 한다.

## 용어

- **룸 세션**: 상담원과 고객이 합류해 화면을 공유하는 하나의 co-browsing 작업 공간. 생성 직후에는 아직 아무도 합류하지 않은 대기 상태다.
- **시리얼 번호**: 고객에게 전달되어 같은 룸 세션을 찾아 들어오게 하는 짧은 일회성 코드. 사람이 읽고 옮겨 적을 수 있는 길이(6자리)다.
- **만료 시각**: 발급된 시리얼 번호가 유효한 마지막 시점. 이 시각이 지나면 해당 번호로는 더 이상 룸에 합류할 수 없다.
- **상담원 / 고객**: 상담원은 룸 생성을 요청하는 쪽, 고객은 전달받은 시리얼 번호로 합류하는 쪽이다.

## 사용자 스토리 / 시나리오

- 상담원으로서, 고객과 화면을 공유하기 위해 새 co-browsing 세션을 만들고 고객에게 전달할 시리얼 번호를 받고 싶다.
- 상담원으로서, 발급받은 시리얼 번호가 언제까지 유효한지 알고 싶다. 그래야 고객에게 "이 번호는 N분 안에 입력해 달라"고 안내할 수 있다.

주요 흐름(사용자 관점):

```
상담원: "새 세션 시작" 요청
   │
   ▼
시스템: 새 룸 세션을 만들고 (대기 상태),
        그 룸에 연결되는 새 시리얼 번호를 발급
   │
   ▼
상담원: 시리얼 번호 + 만료 시각을 돌려받음
   │
   ▼
상담원: 고객에게 시리얼 번호 전달 (구두/복사)
```

## 기능 요구사항 (FR)

- FR-1. 시스템은 상담원의 단일 룸 생성 요청을 받아, 새 룸 세션 하나와 그에 연결된 시리얼 번호 하나를 발급해야 한다. 요청에는 별도의 입력값이 필요 없다.
- FR-2. 시스템은 생성된 룸 세션을 "대기 상태"(아직 아무도 합류하지 않음)로 만들어야 한다.
- FR-3. 시스템은 응답으로 발급된 시리얼 번호와 그 시리얼 번호의 만료 시각을 함께 돌려줘야 한다.
- FR-4. 시스템은 발급한 시리얼 번호로 나중에 고객이 같은 룸 세션을 찾아 합류할 수 있도록, 시리얼 번호와 룸 세션의 연결을 보관해야 한다.
- FR-5. 시스템은 매 요청마다 다른(고유한) 시리얼 번호를 발급해야 한다. 이미 사용 중인 시리얼 번호와 겹치는 경우 다른 번호를 다시 만들어 발급해야 한다.
- FR-6. 시스템은 사람이 읽고 옮겨 적기 쉬운 길이(6자리)의 시리얼 번호를 발급해야 한다.
- FR-7. 룸 세션과 시리얼 번호 연결을 끝까지 만들지 못한 경우, 시스템은 절반만 만들어진 상태를 남기지 않아야 한다(룸만 생성되고 시리얼이 없는 상태가 외부에 노출되지 않아야 한다).
- FR-8. 룸 생성에 실패한 경우, 시스템은 시리얼 번호나 만료 시각 대신 생성 실패를 알리는 응답을 돌려줘야 한다.

## 규칙 / 제약 (비즈니스 룰)

- 룸 생성 요청은 입력값 없이 처리된다 — 상담원이 채워 넣을 정보 없이 "시작"만으로 새 세션이 만들어진다.
- 시리얼 번호는 발급 시점부터 일정 시간(10분) 동안만 유효하다. 만료 시각은 "발급 시점 + 10분"이다.
- 시리얼 번호는 발급 시점에 유일해야 한다. 활성 상태로 이미 같은 번호가 존재하면 그 번호는 재사용되지 않고 새 번호가 만들어진다.
- 시리얼 번호 충돌로 새 번호 생성을 반복해도 합리적인 횟수(최대 5회) 안에 성공하지 못하면, 그 요청은 실패로 처리되고 절반만 만들어진 룸은 정리된다.
- 생성된 룸 세션의 내부 식별자는 외부 응답에 노출되지 않는다 — 상담원과 고객이 다루는 것은 시리얼 번호뿐이다.
- 만료 시각은 상담원/고객 UI가 남은 시간을 표시(카운트다운)할 수 있도록, 사람이 읽고 비교할 수 있는 절대 시각 형태로 제공된다.

## 비기능 요구사항 (NFR)

- NFR-1. 여러 상담원이 동시에 룸 생성을 요청해도 각 요청은 서로 다른 고유한 시리얼 번호를 받아야 하며, 동시 요청으로 인해 상태가 깨지지 않아야 한다.
- NFR-2. 시리얼 번호는 추측이 쉬운 짧은 코드이므로, 충분히 큰 후보 공간에서 발급되어 우연한 충돌이 드물어야 한다.
- NFR-3. 룸 세션과 시리얼 번호는 서버 메모리에 보관되며, 서버가 재시작되면 초기화된다(영속 저장은 이 단계의 요구사항이 아니다).

## 인수 조건 (Acceptance Criteria)

- [ ] AC-1. (Given 상담원이 입력값 없이 룸 생성을 요청하면) (When 요청이 정상 처리되면) (Then 시스템은 시리얼 번호와 만료 시각을 담은 성공 응답을 돌려준다.)
- [ ] AC-2. (Given 동일한 룸 생성 요청을 연속 두 번 보내면) (Then 두 응답의 시리얼 번호는 서로 다르다.)
- [ ] AC-3. (Given 룸 생성이 성공하면) (Then 응답의 만료 시각은 요청 시점으로부터 10분 뒤의 절대 시각이며, 사람이 읽을 수 있는 형식이다.)
- [ ] AC-4. (Given 룸 생성이 성공하면) (Then 생성된 룸 세션은 "대기 상태"로 존재한다.)
- [ ] AC-5. (Given 룸 생성이 성공하면) (When 응답으로 받은 시리얼 번호로 룸을 조회하면) (Then 방금 만들어진 그 룸 세션으로 연결된다.)
- [ ] AC-6. (Given 새로 발급할 시리얼 번호가 계속 이미 존재하는 번호와 충돌하는 상황이면) (When 충돌이 허용 횟수(5회)를 넘으면) (Then 룸 생성은 실패하고, 절반만 만들어진 룸은 남지 않는다.)
- [ ] AC-7. (Given 룸 생성이 실패하면) (Then 응답에는 시리얼 번호나 만료 시각이 없고, 생성 실패를 알리는 내용만 담긴다.)
- [ ] AC-8. (Given 서버가 재시작되면) (Then 이전에 발급된 룸 세션과 시리얼 번호는 더 이상 유효하지 않다.)
