# services — 작업 규칙

> 개념·역할은 [`README.md`](README.md) 참조. 이 문서는 작업 시 지킬 규칙이다. 공통 규칙은 [루트 `CLAUDE.md`](../../CLAUDE.md).

서비스는 **유즈케이스**를 담는다. 도메인 객체와 포트를 조합해 "사용자의 한 가지 행동"이 일으키는 흐름을 오케스트레이션하고, 트랜잭션/일관성 경계를 책임진다.

## 의존 규칙

✅ `domain`(엔티티·포트)에만 의존한다
🚫 `infrastructure` **구현체를 직접 참조하지 않는다** — 저장소가 필요하면 도메인 포트(인터페이스)를 생성자로 주입받아 쓴다
🚫 `interfaces` / `app` 의존 금지 (HTTP·gin·huma 등 트랜스포트 타입이 여기로 새어 들어오면 안 된다)

## 패턴

- **생성자 주입**: 필요한 포트/하위 서비스를 `NewXxx(...)` 인자로 받아 구조체 필드로 보관한다. 전역 상태 금지
- **유즈케이스 메서드**: `Create`, `Activate`, `End`처럼 행동 단위로 노출한다. 첫 인자는 `ctx context.Context`
- **유즈케이스 경계 에러로 번역**: 도메인 sentinel을 그대로 위로 흘리기보다, 트랜스포트가 상태 코드로 매핑하기 쉬운 유즈케이스 에러로 한 번 변환한다(예: 여러 도메인 에러 → `ErrInvitationInvalid`). interfaces가 도메인 내부 sentinel을 직접 알 필요가 없게 한다
- **계층화된 서비스**: 단일 관심사(영속 상태만 다루는 서비스)와 상위 조율자(여러 서비스·휘발 상태까지 묶는 코디네이터)를 분리할 수 있다. 상위 조율자는 하위 서비스를 주입받아 흐름만 엮고, 규칙 자체는 도메인에 둔다
- 부분 실패가 치명적이지 않은 단계(예: 알림용 부가 전이)는 흐름을 끊지 말고 에러를 함께 반환해 호출자가 로깅하도록 한다
- 외부에 노출하는 식별자는 트랜스포트로 넘어갈 수 있으므로 필요 시 opaque한 형태(string 등)로 변환해 돌려준다
