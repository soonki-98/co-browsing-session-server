# infrastructure — 작업 규칙

> 개념·역할은 [`README.md`](README.md) 참조. 이 문서는 작업 시 지킬 규칙이다. 공통 규칙은 [루트 `CLAUDE.md`](../../CLAUDE.md).

infrastructure는 도메인이 선언한 **포트의 구체 구현**을 둔다(저장소, 외부 시스템 클라이언트). 기술 세부(메모리/DB/캐시/HTTP 클라이언트)는 여기에 가두고, 안쪽 레이어는 포트 인터페이스로만 이를 본다.

## 의존 규칙

✅ `domain`(구현할 포트·다룰 엔티티)에만 의존한다
🚫 `services` / `interfaces` / `app` 의존 금지 (depguard가 강제)
🚫 비즈니스 규칙을 두지 않는다 — 구현은 "어떻게 저장/조회하느냐"만 책임지고, "무엇이 유효한가"는 도메인의 몫

## 패턴

- 구현은 **도메인 포트 인터페이스를 만족**시킨다. 시그니처는 포트를 따르고, 도메인 타입을 입출력으로 쓴다
- 생성자 `NewXxxRepository(...)`로 만들어 app에서 주입한다. 내부 상태(맵, 커넥션 풀 등)는 캡슐화한다
- 저장소는 도메인 에러 규약을 지킨다 — 없으면 `domain ...ErrNotFound`를 반환하는 식으로, 호출자가 `errors.Is`로 분기할 수 있게 한다
- 공유 가변 상태(in-memory 맵 등)는 뮤텍스로 보호하고 `go test -race`로 검증한다
- 구현 교체(예: in-memory → Redis)는 같은 포트를 만족하는 새 타입을 추가하고 app의 주입부만 바꾸면 되도록 — 포트 시그니처를 깨지 않는다
