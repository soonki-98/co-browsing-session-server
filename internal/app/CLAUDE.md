# app — 작업 규칙

> 개념·역할은 [`README.md`](README.md) 참조. 이 문서는 작업 시 지킬 규칙이다. 공통 규칙은 [루트 `CLAUDE.md`](../../CLAUDE.md).

app은 **컴포지션 루트**다. 구체 타입을 생성해 생성자에 주입하고 라우터를 조립하는, 유일하게 "모든 레이어를 아는" 곳이다. 의존성 그래프의 배선이 여기 한곳에 모이므로, 구성 변경(예: in-memory → Redis)은 이 레이어만 고치면 된다.

## 의존 규칙

✅ 모든 레이어를 import 할 수 있다(조립을 위해) — depguard 규칙 없음
🚫 그래도 **비즈니스 로직·유즈케이스 흐름을 두지 않는다**. 규칙은 domain/services에, 변환은 interfaces에. 여기는 "무엇을 무엇에 꽂을지"만

## 패턴

- `New()`는 **안쪽 → 바깥쪽 순서**로 조립한다: domain(순수 값 생성) → infrastructure(포트 구현) → services(유즈케이스) → interfaces(어댑터) 주입
- **인터페이스가 아니라 구체 타입을 여기서 고른다**. 어떤 구현을 쓸지 결정하는 유일한 지점 — 다른 레이어는 포트만 본다
- 트랜스포트 조립: huma 핸들러는 라우터에 등록하고, raw 업그레이드가 필요한 WebSocket 핸들러는 gin 엔진에 직접 등록한다
- 서버 구동(`Run`)과 엔진 노출(`Engine`)을 분리해, 테스트·OpenAPI 추출이 서버를 띄우지 않고 in-process 요청을 보낼 수 있게 한다
- 통합 테스트는 이 조립 결과(실제 의존성 그래프)를 그대로 띄워 엔드투엔드로 검증한다 — 과한 목 대신 실제 배선을 쓴다
