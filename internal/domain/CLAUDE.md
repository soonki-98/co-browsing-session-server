# domain — 작업 규칙

> 개념·역할은 [`README.md`](README.md) 참조. 이 문서는 작업 시 지킬 규칙이다. 공통 규칙은 [루트 `CLAUDE.md`](../../CLAUDE.md).

도메인은 시스템의 **가장 안쪽 핵심**이다. 기술 선택(웹 프레임워크, DB, 직렬화)과 무관한 순수한 비즈니스 규칙만 둔다. 다른 모든 레이어가 여기에 의존하므로, 여기서의 변경은 파급이 가장 크다 — 보수적으로 다룬다.

## 의존 규칙

🚫 **다른 내부 레이어를 import 하지 않는다** (services / interfaces / infrastructure / app 전부 금지, depguard가 강제)
🚫 웹/DB/직렬화 등 **기술 프레임워크 의존 금지**. 표준 라이브러리와 범용 유틸(예: `uuid` 같은 순수 값 생성)까지만 허용
✅ 엔티티·값 객체·도메인 에러·포트 인터페이스 정의

## 패턴

- **엔티티/값 객체**: 식별자와 불변식, 행위(메서드)를 함께 가진다. 상태 전이는 검증을 거쳐 메서드로만 바꾼다 — 외부에서 필드를 임의로 세팅하지 않는다 (예: `roomsession` 의 상태 전이 메서드)
- **도메인 에러는 sentinel**: `var ErrNotFound = errors.New("...")` 형태로 패키지에 선언하고, 바깥 레이어는 `errors.Is`로 판별한다
- **포트(인터페이스)는 도메인이 선언한다**: `Repository`, `Generator`처럼 "이런 기능이 필요하다"를 인터페이스로 두고, 구현은 infrastructure가 제공한다. 인터페이스는 도메인이 실제로 필요로 하는 최소 메서드만 가진다
- **타입드 식별자**: 원시 string 대신 의미 있는 타입(`RoomID`, `SerialNumber`)으로 식별자를 표현해 혼용을 막는다
- 시간·랜덤처럼 부수효과가 필요한 값은 포트로 추상화해 주입받는다(테스트 가능성)
